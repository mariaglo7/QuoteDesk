# QuoteDesk

QuoteDesk helps creative freelancers turn a client enquiry into a priced offer, a reply message and a PDF in minutes.

**Live demo:** https://mariaglo7.github.io/QuoteDesk/ (data stays in your browser; Claude needs your own API key)

It started from the quoting work of Maria Glowacka (Design by Maria), where one quote took between 30 minutes and 3 hours, and is built for other freelancers too: graphic and web designers, photographers and social media managers.
RGU module CM3026 Autonomous Coding, 2026.

## What it does

1. **Paste the client's message.** Claude reads it and suggests services from your price list, the language, the client type and what is missing.
2. **Check the offer on the Desk.** Prices always come from your price list and client type multipliers, never from the AI. Each price shows whether it is below, within or above the market range you researched.
3. **Explain the value.** A "What you gain" section explains what the client gets from working with a person, without promised numbers or guarantees.
4. **Send it.** A reply message in Polish or English, a PDF in your colours and logo, and optionally a signed link to an online summary with a "Let's talk" button.
5. **Follow up.** The offers list shows the status of each offer and drafts a polite follow up after 3 days.

Interface in Polish and English (PL/EN switch in the top bar). Currencies: GBP, EUR, PLN.

## Run it

**Website (anyone):** open the demo or serve the `web` folder.

```bash
npm install
npm run build:site
node tools/serve.mjs _site 4173
```

Then open http://localhost:4173. On first start you land in Settings: fill in your business profile and enter your prices.

**Claude in the website version:** paste your own Anthropic API key in Settings. The key stays in that browser only, is never exported in backups, and requests are billed to your Anthropic account. Without a key everything works except the AI parts, which fall back to fixed templates.

**claude.ai artifact (the author's setup):** `web/index.html` with the files in `web/` can be published as a claude.ai artifact with the `sample`, `db`, `assets`, `user` and `downloads` capabilities; Claude then runs on the owner's plan and data is stored in the owner's private artifact database.

**Online offer page (optional):** upload `hostinger/oferta` to your own PHP hosting following `hostinger/oferta/INSTRUKCJA.md`, then set its address and copy the link key from Settings into `config.php`.

## Tests

```bash
npm test
```

171 automated tests (Node `node:test`) cover pricing, market ranges, Claude prompt rules and response parsing, signed links, backups, the PDF layout and the bilingual interface text. `contact.php` was checked by hand on PHP 8.5 with the links in `hostinger/test-links.txt` (generated by the tests).

## Project layout

| Path | What it is |
|---|---|
| `web/src/` | Logic without DOM: pricing, text, Claude prompts and parsing, links, backup, AI adapter |
| `web/src/pdf/` | PDF layout engine and blocks (jsPDF) |
| `web/src/ui/` | Views: paste message, Desk, offers, settings |
| `hostinger/oferta/` | Optional public offer page and `contact.php` |
| `tests/` | Automated tests; fixtures are fictional |
| `docs/` | Specs, plans, evidence and assessment documents |
| `CLAUDE.md` | Instructions for AI coding agents working on the repository |

## How AI was used

The problem and first idea came from Maria's own quoting work. Claude (Claude Code, Opus) then helped to explore design directions, write the specification and plans, implement the code in small tested steps and review it. Maria made the decisions; every change was tested and committed separately so it can be inspected and reverted. Details and examples of corrections are in `docs/`.

## Privacy and limits

- Client messages are sent to Anthropic when Claude is used. Remove sensitive details first.
- In the website version data lives in browser storage; use Settings, Backup to keep a copy.
- The API key in the browser is visible to anything running on that page; use a key with a spending limit.
- The value text and messages are drafts: always read them before sending.
- Offers are not invoices and there is no payment handling.
